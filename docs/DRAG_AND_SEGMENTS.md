# ドラッグ適用と区間ごとのイージング

このページは、HL_Ezing の「トラックバーへドラッグして適用」と
「中間点ごとに違うイージングを設定する」機能の使い方と、
AviUtl2 がバージョンアップしたときの更新方法をまとめたものです。

リバースエンジニアリングに詳しくない人でも更新できるように、
「まず何を見るか」「どこを直すか」の順番で書いています。

---

## 1. できること

- HL_Ezing の「適用」ボタンを、AviUtl2 のオブジェクト設定にある
  `X` / `Y` / `Z` / `中心X` などの行へドラッグして適用できます。
- ドラッグ中は、ドロップ先の行が枠でハイライトされます。
- 中間点がある場合、**マウスを離したときのシークバー位置の区間だけ**を
  現在のカーブIDで上書きします。
- 画面下の「区間」バーから区間を選べます。
  区間をクリックすると、AviUtl2 のカーソルがその区間の先頭へ移動します。

### 最初の適用について

まだ HL_Ezing が適用されていないトラックバーへドラッグした場合は、
そのトラックバーの**全区間**を現在のカーブIDで初期化します。
その後、中間点を追加してから別の区間へドラッグすると、
その区間だけが上書きされます。

これは AviUtl2 のトラックバーが「トラック全体で1つの移動方法」を持つためです。
区間ごとに別の移動方法を混在させることはできないので、
HL_Ezing 側で区間ごとのカーブIDリストを持たせています。

---

## 2. 使い方

### 2.1 1区間だけに適用する

1. オブジェクトを選択し、オブジェクト設定を開きます。
2. HL_Ezing でカーブIDを選び、グラフを編集します。
3. 「適用」ボタンを押したまま、`X` などの行までドラッグします。
4. 行が枠でハイライトされたら、その場で離します。

D&Dは設定画面で無効化できます。無効時も「適用」ボタンのクリック、
トラックピッカー、右クリックメニューは使用できます。

グループ化された `X` / `Y` / `Z` などへドロップした場合、
設定の「グループ項目へまとめて適用（D&D）」がONなら同じグループ全体へ、
OFFならドロップした1項目だけへ適用します。

### 2.2 中間点ごとに変える

1. まず、中間点がない状態で一度適用します。
2. AviUtl2 側で中間点を追加します。
3. シークバーを、変更したい区間の位置へ移動します。
4. HL_Ezing で別のカーブIDを選びます。
5. 「適用」ボタンをその行へドラッグして離します。

このとき、**シークバーがある区間だけ**が新しいIDになります。  
他の区間のIDは保持されます。

区間数にかかわらず、グラフの始点・終点Yをそのままトラック値へ反映します。
端点を 0/1 に正規化することはありません。

### 2.3 区間バー

中間点があると、グラフの下に `区間 1 2 3 ...` が表示されます。

- 現在のシークバー位置の区間が青く表示されます。
- 区間をクリックすると、AviUtl2 のカーソルがその区間の先頭へ移動します。
- シークバーや区間を動かすと、AviUtl2 のイベント通知で区間バーが更新されます。
  ポーリングは行いません。

区間バーは「時間の区間」を選ぶためのものです。
どの区間にどのカーブIDが入っているかを確認したい場合は、
その区間へシークバーを移動して、HL_Ezing のID欄を確認してください。

### 2.4 全ての区間・全てのトラックへ適用

- 「適用」ボタンを**クリック**した場合のトラックピッカーは、
  選択した区間へ適用します。
- 「全てに適用」を選んだ場合は、対象トラックの全区間を
  現在のカーブIDで置き換えます。

### 2.5 グラフ編集の操作

- `Ctrl+Z`: 元に戻す
- `Ctrl+Y` / `Ctrl+Shift+Z`: やり直す
- アンカーまたはハンドルを右クリック:
  - 「ハンドルを分離」: 左右を別々に動かす
  - 「ハンドルを統合」: 左右の向きを反対に揃える。長さは左右で独立
- グラフをクリックした後に `Space`: AviUtl2 本体の再生 / 停止
- メイン領域とプリセット欄の仕切りバー中央の矢印ボタン:
  - プリセット欄の表示 / 非表示

Undo / Redo は HL_Ezing 内のカーブ編集が対象です。
トラックバーへの適用そのものは AviUtl2 本体の Undo を使用してください。

## 3. 内部の仕組み（やさしい説明）

AviUtl2 の公開SDKには、
「マウスの下にあるトラックバーはどれか」を取得するAPIがありません。
また、オブジェクト設定は Direct2D で描画されており、
トラックバーごとに HWND があるわけでもありません。

そのため HL_Ezing は、**自分自身のプロセス内のメモリ**を読み取って、
オブジェクト設定のコントロールを見つけています。
外部プロセスへの注入や管理者権限は不要です。

見つけているもの:

- `Component::EffectItemNumberControl`
  - 数値設定1行分のコントロール
- `Control::SliderInputControl`
  - 実際のスライダー部分
- `Component::EffectSetting`
  - エフェクト名（`座標` など）の取得

### vtable と RTTI

C++ のクラスは、実行時に「vtable」と呼ばれる関数表へのポインタを持ちます。
HL_Ezing はこの vtable を、クラス名（RTTI）から自動で探します。

そのため、AviUtl2 のアップデートでアドレスが変わっても、
**クラス名とレイアウトが同じなら自動で追従**します。

## 4. AviUtl2 がバージョンアップしたとき

### 4.1 まず診断ログを出す

1. AviUtl2 でオブジェクト設定を開きます。
2. メニューの  
   `HL_Ezing` → `ドラッグ適用の診断情報をログ出力`  
   を実行します。
3. AviUtl2 のログに `HL_Ezing trackbar diagnostics:` が出ます。

HL_Ezing の設定画面にある「ドラッグ診断をログ出力」でも同じです。

### 4.2 ログの見方

正常なとき:

```json
{
  "version": 2011400,
  "profile": "AviUtl2 2.1.x",
  "vtables": {
    "effect_item_control": "0x...",
    "slider_input": "0x...",
    "effect_setting": "0x..."
  },
  "targets": [
    {
      "item": "X",
      "effect": "座標",
      "rect": { "x": 1490, "y": 515, "w": 300, "h": 20 },
      "visible": true
    }
  ]
}
```

- `vtables` が `null`  
  → クラス名の解決に失敗しています。  
  → `src/trackbar.rs` の `CLASS_...` を確認します。
- `vtables` は出るが `targets` が空  
  → レイアウトのオフセットが変わっています。  
  → 下の `LayoutProfile` を更新します。
- `targets` は出るがハイライト位置がずれる  
  → `slider_rect` か DPI の扱いを確認します。
- `effect` が空  
  → `setting_effect_base` / `effect_base_name` を確認します。

### 4.3 直す場所は1か所

`src/trackbar.rs` の `LAYOUT_2_1_X` を更新します。

```rust
const LAYOUT_2_1_X: LayoutProfile = LayoutProfile {
    label: "AviUtl2 2.1.x",
    item_control_item: 0x278,
    item_control_size: 0x1B48,
    item_control_context: 0x0E8,
    setting_effect_base: 0x0F8,
    effect_base_name: 0x40,
    item_name_wstring: 0x10,
    slider_visible: 0x0C,
    slider_rect: 0x50,
};
```

| フィールド | 意味 | 2.1.14 の値 |
| --- | --- | ---: |
| `item_control_item` | 数値項目データへのポインタ | `0x278` |
| `item_control_size` | 1行分コントロールのサイズ | `0x1B48` |
| `item_control_context` | 親エフェクト設定へのポインタ | `0x0E8` |
| `setting_effect_base` | エフェクト本体へのポインタ | `0x0F8` |
| `effect_base_name` | エフェクト名へのポインタ | `0x40` |
| `item_name_wstring` | アイテム名（`std::wstring`） | `0x10` |
| `slider_visible` | 表示フラグ | `0x0C` |
| `slider_rect` | 矩形（x, y, w, h） | `0x50` |

`SliderInputControl` 自体の位置は固定値ではありません。
オブジェクト内の vtable を走査して自動検出しています。
参考値は 2.1.14 が `+0x568` / `+0x1058`、2.1.3a が `+0x540` / `+0x1000` です。

### 4.4 それでも直らないとき

次の情報があると調査しやすいです。

- AviUtl2 のバージョン
- 診断ログの `vtables` と `targets`
- ドラッグした行の名前（`X`、`中心X` など）
- ハイライトが出るか、位置がずれるか

`vtables` が null の場合は、クラス名が変わった可能性があります。
その場合は AviUtl2 の `.rdata` に含まれる
`EffectItemNumberControl` / `SliderInputControl` の文字列を確認し、
`CLASS_...` を更新してください。

## 5. 区間ごとのカーブIDの保存形式

UI に `ID01`〜`ID64` のような項目を並べないため、区間IDリストは
トラックバーではなく **HL_Ezing 側の割り当てテーブル**に保存しています。

- トラックバーの移動方法パラメータは次の2個だけです。

```text
1000000000 + assignment_id, nonce
```

- `assignment_id` はプラグイン内の「区間IDリスト」への番号です。
  カーブIDの入力上限が 999999 なので、10億以上を割り当てIDと区別しています。
- `.tra2` は `obj.getpoint("index")` で現在の区間番号を取得し、
  モジュール関数 `getsegment(assignment_id, index)` で
  その区間のカーブIDを引きます。
- 割り当てテーブルはプロジェクトファイルの
  `hl_ezing_segment_assignments` に保存されます。

古いバージョンの `curve_id, nonce` 形式も読み込めます。
その場合、次に適用したときに自動で新しい割り当て形式へ移行します。

旧ベータの `[0, id0, id1, ..., nonce]` 形式は、再適用時に
区間IDリストを読み取って新しい割り当て形式へ移行します。
ただし旧ベータのプロジェクトを開いただけでは、AviUtl2 のスクリプト
パラメータ数の制約により線形表示になる場合があります。
その場合は一度 HL_Ezing を再適用してください。

この方式により、何区間あってもトラックバーの設定項目は2個のままです。

## 6. 既知の制限

- プラグインの再ロード（AviUtl2 を終了せずに DLL を差し替える操作）には
  対応していません。WebView2 とウィンドウクラスはプロセス終了まで保持されます。
  DLL を更新する場合は AviUtl2 を終了してください。
- 旧ベータの区間リスト形式は、読み込み直後は線形表示になる場合があります。
  一度再適用すると新しい割り当て形式へ移行します。
- 単一項目への適用は、選んだトラックバー1つだけが対象です。
  同じグループの項目へまとめて適用したい場合は「全てに適用」を使ってください。
- Space の本体転送は、AviUtl2 のメインウィンドウを
  `aviutl2Manager` クラス（見つからない場合は同一プロセスの最大ウィンドウ）
  として探します。将来クラス名が変わった場合は `src/window.rs` を更新してください。

## 7. ビルドと確認

```powershell
npm --prefix frontend install
npm --prefix frontend run build
cargo test
cargo clippy --all-targets -- -D warnings
au2 develop
```

リリース:

```powershell
au2 release
```

AviUtl2 が起動中だと `target/debug/hl_ezing.dll` がロックされて
ビルドに失敗することがあります。その場合は AviUtl2 を終了してから
`au2 develop` を実行してください。
